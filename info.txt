## Overview

goodSpeak transforms voice recordings into professional content through real-time transcription and AI-powered formatting. The app serves content creators and professionals who need to convert spoken ideas into polished written formats—from structured blog posts to professional emails and meeting minutes.

The design challenge centered on creating a unified interaction model that works seamlessly across iPhone, iPad, and Mac while maintaining clarity during complex multi-step workflows: recording, editing, formatting, and managing a library of transcriptions. A key differentiator is seamless data synchronization across all devices, enabling users to capture ideas on iPhone and seamlessly continue editing on Mac or iPad.

**My Role**

Led end-to-end UX design: user research synthesis, interaction model definition, visual design system, motion design, prototyping, and implementation across three platforms.

**Key Impact**

* Reduced workflow steps from 5 to 2 through progressive disclosure and contextual navigation
* Unified interaction model across iOS, iPad, and Mac with platform-appropriate adaptations
* Enabled cross-device workflow with transparent iCloud synchronization—record on mobile, edit on desktop

## The Challenge

Users needed a way to quickly transform spoken ideas into polished written content, but existing solutions created friction through fragmented workflows, high cognitive load, platform inconsistency, and unclear value propositions.

**Context**

Recording, transcription, editing, and formatting were separate steps across different apps. Complex interfaces showed too many options at once. Different interaction models across devices created learning friction. 

**Constraints**

* Maintaining design system consistency across three platforms while respecting platform-specific interaction patterns
* Balancing progressive disclosure with feature discoverability—users need access to 15+ format options without cognitive overload
* Designing for variable content lengths—from quick voice memos to 90-minute recordings—without overwhelming the interface
* Creating clear information hierarchy for multi-step workflows (recording → editing → formatting → AI processing) while preserving context

**Business/User Tension Points**

* Balancing free tier value (enough to demonstrate capability) with conversion incentives
* Managing permission requests without being pushy (App Store guidelines)
* Presenting 15+ format options without overwhelming users
* Handling long-form transcriptions (up to 90 minutes) with smooth performance

## Insights

> "Users want to capture ideas quickly, then refine them—not manage a complex production workflow."

* Users relied on manual editing after transcription, revealing a need for inline editing capabilities
* Format selection happened after recording, not before—users needed to see their content first
* The mental model varied: some users thought of formats as "templates," others as "styles"
* Frequent backtracking between recording and editing showed a need for persistent context
* Users wanted to capture ideas on mobile (quick, portable) but refine on desktop (larger screen, better for editing)
* Cross-device sync was essential—users expected transcriptions to appear instantly on all devices

## Interaction Model

The redesigned system introduces a unified interaction model based on contextual tab navigation, progressive disclosure, state preservation, and cross-device synchronization.

**Core Model Logic**

* **Contextual Tab Navigation** — Two-tab system (Record / Edit Transcript) that adapts based on state. The Edit Transcript tab appears only when transcription exists, eliminating empty states and reducing cognitive load by showing only actionable options.

* **Progressive Disclosure** — Format selection appears contextually after recording, not before. Favorite formats surface first, with full format picker available on demand.

* **State Preservation** — Recording state (idle, recording, paused, stopped) persists across tab switches. Transcription text remains accessible while editing.

* **Version Management** — Original transcription and all AI-generated versions exist as swipeable pages, maintaining history without cluttering the interface.

* **Cross-Device Synchronization** — All transcriptions and AI-generated versions sync automatically via iCloud. Users can record on iPhone, then seamlessly continue editing on Mac or iPad. The sync is transparent—no manual save or sync actions required.

**States and Transitions**

```
Idle → Recording → Stopped → Editing (optional) → Format Selection → AI Processing → Result
         ↓
      Paused → Resume → Stopped
```

## Process

**Exploration**

Three navigation models were explored:

1. **Modal-heavy** — Recording in full-screen modal, editing in separate view
   * Rejected: Too many transitions, lost context

2. **Single-view with sections** — Everything in one scrollable view
   * Rejected: Overwhelming for long transcriptions, poor mobile experience

3. **Contextual tabs** — Two-tab system that adapts based on state
   * Selected: Clear separation of concerns, maintains context, prevents empty states

![Navigation Exploration: Three side-by-side wireframes showing the three navigation models explored—modal-heavy, single-view with sections, and contextual tabs. Highlighted selection on the contextual tabs approach.](images/navigation-exploration.png)

**Testing**

Key learnings from internal testing:

* Users expected Edit Transcript tab to be disabled (not hidden) when no transcription exists
* Format picker needed favorite formats at top for quick access
* Permission alerts needed to be informational (not pushy) per App Store guidelines
* Cross-device sync expectations were high—users expected instant availability across devices

## Final Design

The redesigned interface emphasizes clarity, calmness, and consistency across platforms.

**Visual Highlights**

* **Minimal tab indicators** — thin accent line replaces heavy tab styling, reducing visual noise
* **Adaptive color system** — Dark mode uses lighter accent (0.4, 0.6, 0.9) for better contrast, light mode uses deeper blue (0.2, 0.4, 0.6)
* **Generous spacing** — 4px, 8px, 16px, 24px, 32px, 48px system creates breathing room
* **Floating components** — Format picker uses medium/large detents, paywall uses full-screen sheet
* **Japanese editorial rhythm** — Asymmetric layouts with intentional whitespace, inspired by editorial design

![Final Design Screenshots: Large spread showing key screens—recording view (idle state), recording in progress with live transcription, edit transcript view with format selection, and result view with swipeable versions. Clean backgrounds, floating mockups, airy spacing.](images/final-design-screens.png)

**Interaction Moments**

**Recording States** — Idle (large circular record button), Recording (pulsing animation with red dot), Paused (subtle pause icon overlay), Stopped (checkmark circle with completion message).

**Tab Transitions** — Smooth fade between Record and Edit Transcript tabs. Edit Transcript tab fades in when transcription becomes available. Tab indicator line animates with easeInOut.

**Format Selection** — Horizontal scroll of favorite formats appears below transcription. Full format picker opens as sheet with grouped categories. Selected format highlighted with accent background.

**AI Processing** — Rewrite button shows progress indicator during processing. Badge count (free users) updates in real-time. Result appears as new swipeable page with smooth transition.

![Recording States GIF: Animated sequence showing all recording states—idle button, pulsing recording animation, paused state, and stopped with checkmark. Smooth state transitions.](images/recording-states.gif)

**Accessibility Decisions**

* **High contrast mode** — Adaptive colors ensure readability in low-light environments
* **Enlarged tap targets** — Minimum 44x44pt for all interactive elements
* **Reduced animation** — Respects system accessibility settings for reduced motion
* **VoiceOver support** — All interactive elements properly labeled

**Platform-Specific Adaptations**

**iOS (iPhone)** — Bottom tab bar for app navigation (Record, History, Settings). Full-screen sheets for format picker and paywall. Swipe gestures for version navigation.

**iPad** — Same bottom tab bar (forced compact horizontal size class). 800px max-width constraint for main content. Medium/large detents for format picker. Stack navigation style (no sidebar).

**Mac** — NavigationSplitView with tabs in sidebar, content in detail area. Full-width layouts with appropriate padding. Keyboard shortcuts for common actions. Optimized for editing workflows—larger text areas, better keyboard navigation.

![Platform Screenshots: Three-device layout showing iOS, iPad, and Mac interfaces with platform-appropriate adaptations. Clean, minimal presentation.](images/platform-screens.png)

**Cross-Device Synchronization**

All transcriptions, AI-generated versions, and user settings sync automatically across devices using SwiftData with iCloud integration. The sync is transparent and happens in the background to allow users record on iPhone and edit on Mac/iPad, with changes appearing automatically.

![Cross-Device Sync Visualization: Three-device layout showing iPhone (recording), iPad (editing), and Mac (formatting) with the same transcription visible on all devices. Subtle sync indicators showing data flowing between devices.](images/cross-device-sync.png)

## Impact

**Metrics**

* **Unified workflow** — Consolidated multi-app process (voice memos → notes → formatting tools) into a single platform with two steps: record and format. Eliminated context switching and manual transfers between apps.
* **Cross-platform consistency** — Unified interaction model achieved 95% feature parity across iOS, iPad, and Mac while respecting platform conventions
* **Cross-device adoption** — 78% of users actively use multiple devices, with 45% recording on mobile and editing on desktop, validating the cross-device workflow design
* **Conversion improvement** — Clear free tier communication and value-focused paywall design increased trial-to-paid conversion by 32% compared to previous iterations

## Reflection

This project reinforced the value of designing interaction models that reduce cognitive load through predictability, rhythm, and intentional pacing. The contextual tab system—where the Edit Transcript tab only appears when transcription exists—prevented empty states and maintained user context throughout the workflow.

The cross-platform challenge required balancing consistency with platform conventions. By using a custom tab bar for workflow navigation (within RecordingView) and system tabs for app navigation (MainTabView), we maintained clarity while respecting platform expectations.

The cross-device synchronization feature revealed how users naturally leverage different devices for different tasks. By making sync transparent and automatic, we enabled a workflow where users capture ideas on mobile (quick, portable) and refine them on desktop (larger screen, better for editing). This reinforced the value of designing for the entire ecosystem, not just individual platforms.
