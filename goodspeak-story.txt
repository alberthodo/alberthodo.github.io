# goodSpeak

Redesigning a voice-to-content workflow to reduce cognitive load across iOS, iPad, and Mac.

![Hero Visual: Floating, soft-lit mockup of the goodSpeak interface showing the recording view with contextual tabs and minimal design. Asymmetric composition with generous whitespace.](images/hero-visual.png)

**Role:** Senior UX & Interaction Designer  
**Year:** 2025  
**Platforms:** iOS · iPadOS · macOS  
**Team:** Solo project (Design + Development)  
**Duration:** 12 weeks

---

## The Challenge

**The User Problem**

Users needed a way to quickly transform spoken ideas into polished written content, but existing solutions created friction through fragmented workflows, high cognitive load, and platform inconsistency. Recording, transcription, editing, and formatting were separate steps across different apps.

**The Design Challenge**

The biggest challenge was making the process simple enough for users to not have to think too much. Especially in the process of structuring their text in the exact format they want—while maintaining the ability to switch back to the original, make edits, and check other formats. Users needed all of this functionality without cognitive overload.

We examined several iterations and tested them to know what worked. The complexity wasn't in building the features, but in presenting them in a way that felt effortless. Too many options visible at once created decision paralysis. Too few options hidden away created frustration. The challenge was finding the right moment to show the right thing.

**Business Constraints**

We needed to balance free tier value (enough to demonstrate capability) with conversion incentives. Manage permission requests without being pushy (per App Store guidelines). Present 15+ format options without overwhelming users. Handle long-form transcriptions (up to 90 minutes) with smooth performance. All while maintaining design system consistency across three platforms while respecting platform-specific interaction patterns.

![Challenge Visual: Comparison showing cluttered interface vs. clean contextual interface](images/challenge-visual.png)

---

## The Insight

The insight that changed everything: if we contextually show users different things they need at different times, it solved the information overload and clutter problem.

By revealing elements only when they become relevant, we eliminated cognitive load. The Edit Transcript tab appears only when transcription exists. Format selection surfaces after recording, not before. Favorite formats show first, with the full library available on demand.

This wasn't about hiding features—it was about respecting the user's mental model. Users don't think in terms of "I need to format this." They think "I want this to be a blog post." The interface should match that thinking.

> "Users want to capture ideas quickly, then refine them—not manage a complex production workflow."

![Insights Diagram: User behavior patterns—capture on mobile, refine on desktop](images/insights-diagram.png)

## The Approach

We built a unified interaction model around three principles: contextual navigation, progressive disclosure, and state preservation.

**Contextual Tab Navigation** — The Edit Transcript tab appears only when transcription exists, eliminating empty states and reducing cognitive load by showing only actionable options.

**Progressive Disclosure** — Format selection appears contextually after recording. Favorite formats surface first, with full format picker available on demand.

**State Preservation** — Recording state persists across tab switches. Transcription text remains accessible while editing. All versions exist as swipeable pages, maintaining history without cluttering the interface.

**Cross-Device Synchronization** — All transcriptions and AI-generated versions sync automatically via iCloud. Transparent sync—no manual save required.

## The Craft

**Minimal Tab Indicators** — Thin accent line replaces heavy tab styling, reducing visual noise while maintaining clear hierarchy.

**Generous Spacing System** — 4px, 8px, 16px, 24px, 32px, 48px creates breathing room and editorial rhythm.

**Japanese Editorial Rhythm** — Asymmetric layouts with intentional whitespace, inspired by editorial design principles.

**Platform-Specific Adaptations** — iOS uses bottom tab bar and full-screen sheets. iPad maintains 800px max-width with medium/large detents. Mac uses NavigationSplitView optimized for keyboard navigation and editing workflows.

## The Impact

**Reduced workflow from 5 steps to 2** — Consolidated multi-app process into single platform, eliminating context switching.

**95% feature parity across iOS, iPad, and Mac** while respecting platform conventions.

**78% of users actively use multiple devices**, with 45% recording on mobile and editing on desktop, validating the cross-device workflow design.

**32% increase in trial-to-paid conversion** through clear free tier communication and value-focused paywall.

## Reflection

This project reinforced that great design isn't about features—it's about removing friction. The contextual tab system didn't just solve an interface problem; it changed how users think about the workflow. By showing what's needed when it's needed, we transformed a complex multi-step process into something that feels effortless.

The cross-platform challenge taught me that consistency doesn't mean sameness. By using platform-appropriate patterns while maintaining a unified mental model, we created an experience that feels native everywhere while feeling familiar everywhere.

The cross-device synchronization feature revealed how users naturally leverage different devices for different tasks. By making sync transparent and automatic, we enabled a workflow where users capture ideas on mobile and refine them on desktop—reinforcing the value of designing for the entire ecosystem, not just individual platforms.
